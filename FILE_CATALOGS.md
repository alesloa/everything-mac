# Portable file catalogs

The file catalog browser stores an immutable offline copy of each imported list, independently from the live index. The catalog picker selects one imported document or all documents. The scope picker searches catalogs alone or catalogs together with a stable native index snapshot. Original drive-letter, UNC, relative and Mac paths remain catalog text. Repeated filename rows are retained with distinct catalog row identities; repeated column headers use their last occurrence.

Import accepts UTF-8 EFU, CSV, TSV and TXT, with an optional UTF-8 BOM. EFU/CSV require a `Filename` or `Path` column containing the full catalog path; TSV uses the same columns with tabs. Optional columns are `Size`, `Date Modified`, `Date Created`, `Attributes` and `Directory`. Size is unsigned bytes, dates are unsigned decimal Windows FILETIME or ISO 8601, attributes are unsigned decimal or `0x` hexadecimal, and Directory is `true`/`false` or `1`/`0`. A trailing slash/backslash or the documented Windows directory attribute also identifies a folder. Empty metadata remains unknown. ISO dates without an offset use the Mac's local time zone. EFU semantics and exact 100-nanosecond FILETIME conversion follow the [public voidtools format documentation](https://www.voidtools.com/en-uk/support/everything/file_lists/#efu-file-format).

CSV and TSV preserve quoted delimiters, doubled quotes and embedded newlines. TXT uses one path per physical line; quoted paths with doubled quotes allow embedded line breaks to roundtrip. A malformed file fails without replacing a previously saved catalog. Native and imported files are not opened during import or search.

Opening a catalog row requires explicitly choosing its imported source prefix and an available local folder. Prefix matching respects path boundaries; Windows mappings accept case differences. Traversal components and symlinks escaping the chosen root are rejected at opening time. A disconnected mapped folder produces the actual filesystem/mapping error. Catalog rows do not run native file actions through a reused numeric ID.

Export supports EFU, CSV, TSV, JSON and TXT. Selected and shown rows retain their displayed order. All matching exports stream every matching row from captured native/catalog snapshots in source order, beyond the display limit. CSV/TSV/EFU date columns use exact decimal FILETIME. Values outside FILETIME's range or precision fail rather than losing date information. JSON writes only the source path and available metadata; timestamps contain exact `seconds` and `nanoseconds`. TXT writes paths only. Optional unknown fields stay empty/absent, while a directory type can emit the documented Windows directory bit. Output is atomically replaced only when writing succeeds; canceling an operation leaves the previous destination in place.

The internal `.efcatalog` file is self-contained and portable between Macs. It contains source filename, catalog identity and optional source metadata. Mapping preferences stay local and are saved separately. The binary file is memory mapped; searching retains at most the configured displayed row limit, and importing/exporting processes one record at a time. No catalog import mutates the native index.
